- `twitter-service.js`: `commitPostTransition` (snapshot → prepare → ONE tx that re-reads the row, refuses on revision/status change, reserves/releases, writes `revision+1`); used by `updateSocialPost`, `approveDraft`, `rejectDraft`, `approveAndSchedule` (fully atomic: edit → approve → schedule computed in memory, no whole-doc restore; identical repeat returns the existing row), `attachMediaToPost` (v2: media edit voids approval), `schedulePost` (new row created in the same transaction), `rejectSocialPost` and the three approval-remix writers. `claimDuePost` bumps `revision`; sweep outcomes settle against OUR claim (`settleClaimed`; a published result is always written); expiry/stale-claim use guarded merge patches; `retrySelfReply`/`listPendingApprovalPosts` use guarded merge patches; `publishApprovedPost` now claims `awaiting_approval→posting` in a transaction before publishing, then delivery-rechecks the claimed row (a double click or token-vs-dashboard race can no longer double-post). Approval binds `approvedHash` (stable hash of copy/self-reply/media/reply target); lifecycle-v2 delivery refuses a row that changed since (`approval-stale`).

Crashed approval/post-now claims (no `scheduledAt`) are swept by claim age.
