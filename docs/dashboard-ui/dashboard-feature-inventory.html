What the sweep turned up

🚫 17 cards are unreachable

Two nav buckets are commented out in the nav array — services (:12262) and onboarding (:12252). Their 15 + 2 card definitions still build on every render and still resolve analyzers, but no nav path reaches them.

Decision needed: delete, or restore the nav entries.

🚫 8 cards render a permanent empty state

local-signals · website-landing · trust-credibility · platform-coverage · visibility-snapshot · newsletter · automation-opportunities · reporting-insights. Each calls buildWorkNeededRows unconditionally with no producer behind it.

Worst placement: platform-coverage is the first step anchor of the Social bucket — the bucket opens on a card that can never fill.

⚠️ Dead allowlist entry

submit-custom-brief is listed in NON_ADMIN_UNLOCKED_CARD_IDS (tier-access-config.js:61) but its card definition is inside an ...(isAdmin ? [...] : []) spread (:9293). Non-admins are allowlisted for a card that never exists for them.

⚠️ One card defined twice

client-mockup (Website, :8478) and client-mockup-creative (Creative Team, :7964) are the same card — same title, same rows, same /api/leadgen/generate-mockup endpoint, same moduleId. Only the id and bucket differ.

⚠️ Two cards with no independent run

site-performance renders seoAuditRows.slice(0, 6) — the first six rows of seo-performance. visibility-snapshot announces its own retirement in its row text. Both read as standalone tiles in the grid.

📤 Only 6 cards are registered scout modules

module-registry.js lists seo-performance, social-preview, multi-device-view, style-guide, design-evaluation, agent-readiness. Everything else that runs does so through a bespoke route or its own component — worth knowing before assuming the runner pipeline covers a card.

📤 Docs coverage: 8 of 86 certified

The June launch audit (CREATIVE-BRIEF-DELIVERABLES-WIRING.md) verified 8 cards with a status column. 20 more have an SSOT doc written since. ~58 cards have no doc at all — mostly derived and placeholder tiles, which is defensible, but it also means no prior document would have surfaced the findings above.

⚠️ Spend surfaces that hide from the cost card

x-profile and Opportunity Signals' Refresh Now both spend real X API credit, and /api/admin/cost-report cannot see it. Treat the Operating Cost card as LLM + image + search spend only.
