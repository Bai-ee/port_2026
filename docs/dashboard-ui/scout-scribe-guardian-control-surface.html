Control surface — what's a knob vs. what's buried

Three modules shape the marketing brief: Scout gathers, Scribe writes, Guardian QAs. Each is steered by some mix of three layers — card config (easy), knowledge files (hand-edit JSON), and hardcoded prompt/constants (code change). This shows, per module, exactly which knobs you can already turn and which are buried.

✅ Card config — UI-editable knob ⚠️ Knowledge file — hand-edit JSON ❌ Hardcoded — code change 📤 Produced but not surfaced

Two things worth flagging

🔗 One file, two stages

brand-voice.json drives both Scribe (tone / framing) and Guardian (voice QA). Editing it re-tunes how content is written and how it's judged — keep that in mind when dialing voice.

⚠️ Guardian reads the wrong config source

runGuardian pulls requireClientConfig (the static registry) + local knowledge files — not the Firestore runtime config. So a Firestore-provisioned client's Guardian card knobs may not flow. Fix this before "dial per client" works. guardian.js:300, 49-56
