Scout · Scribe · Guard

How the three intake-pipeline roles interact — and where to make changes. Lives in features/scout-intake/. Orchestrated by runner.js → runIntakePipeline.

Scout — analyzers (extract signals) Scribe — Haiku LLM (writes copy + brief) Guard — deterministic SEO fact-lock shared / pipeline plumbing

cardId is the single join key threading all three roles together.

Pipeline flow (top → bottom = execution order)

1

Fetch + Synthesize setup

Crawl site, extract design system, run live PSI + AI-SEO audit, LLM brand synthesis.

site-fetcher.js · design-system-extractor.js · pagespeed.js · ai-seo-audit.js · intake-synthesizer.js

produces
sharedResults = { intake, styleGuide, pagespeed, siteMeta }, evidence, aiSeoAudit
used by
Scout (all), Guard (pagespeed + aiSeoAudit)
sharedResults + evidence → fan out to analyzers
2

SCOUT analyzers deterministic + optional Haiku per card

Fans out one analyzer per card in parallel. Extracts & scores signals from evidence/PSI/synthesis. No prose — rules, scores, findings. Tier gates which cards run.

analyzers/index.js → runAnalyzers() · per-card: passthrough.js / runtime.js / pagespeed.js / design-system.js · external: external-scouts.js (weather/reviews/reddit)

in
sharedResults, evidence, userContext, tier
out
analyzerResults.byCard[cardId] = { status, signals, confidence, notes }
analyzerOutputs[cardId].aggregate (richer, P4 skills)
analyzerResults + analyzerOutputs → keyed by cardId
3

SCRIBE copy + brief Haiku 4.5 · 1 call

Reads aggregated signals, writes confident prose per card (short + expanded + recommendation) AND the brief document (headline, summary, priority signals, opportunities). Confidence scales copy length budget. Distinguishes tool failure from site problem.

scribe.js → runScribe() · digest: buildCardDigest() · prompt: buildScribePrompt() · tool: buildScribeTool() · budgets: card-contract.js · voice: card-voice.js

in
analyzerResults, analyzerOutputs, userContext, websiteUrl
out
scribeResult.cards[cardId] = { short, expanded, recommendation }
scribeResult.brief = { headline, summary, … }
scribeResult.cards['seo-performance'] → handed to Guard as existingCard (draft to fact-lock)
4

GUARD SEO fact-lock deterministic · $0

Runs AFTER Scribe, only for the SEO card. Builds a fact pack from live PSI + AI-SEO + builder findings, regenerates the card deterministically, and overwrites Scribe's SEO card. Validation forbids contradicting PSI (can't say "audit failed" when scores exist, can't say "schema missing" when schema present, must name hosting provider when confidence high).

seo-comment-guardian.js → runSeoCommentGuardian() · facts: buildSeoFactPack() · gen: buildDeterministicSeoComment() · gates: validateSeoGuardianComment()

in
pagespeed, aiSeoAudit, seoAggregate, existingCard (Scribe's draft)
out
overwrites scribeResult.cards['seo-performance'] · marked factLocked: true · validationErrors[]
final cards + brief → normalize → Firestore
5

Normalize + Persist write

Merge into dashboard_state/{clientId} via run-lifecycle.cjs → completeRun. Feeds dashboard cards + brief email.

runner.js → normalizeIntakeResult() · api/_lib/run-lifecycle.cjs

Where to make changes

Affect SCOUT

  • New signal / metric: add or edit a per-card analyzer in analyzers/ (model on passthrough.js or runtime.js).
  • Register a card→analyzer: set card.analyzer.impl in the card contract; index.js dispatches by it.
  • External sources (weather/reviews/reddit): external-scouts.js + scoutConfig in client_configs.
  • Tier gating: which cards run free vs paid — pickCards in runner.js.

Affect SCRIBE

  • Tone / wording rules: buildScribePrompt() in scribe.js.
  • Per-role voice: card-voice.js (actionClass → guidance).
  • Copy length budgets / card meta: card-contract.js (short/expanded ranges).
  • Brief fields (headline, summary, opportunities): tool schema in buildScribeTool() + prompt.
  • Confidence → length scaling: buildCardDigest().

Affect GUARD

  • What counts as fact: buildSeoFactPack() (PSI scores, CWV, schema, hosting).
  • How SEO card reads: buildDeterministicSeoComment() (pure, no LLM).
  • Forbidden / required claims: validateSeoGuardianComment().
  • Scope: currently only 'seo-performance'. To guard another card, clone this module + wire a second call after Scribe.
Key mental model: Scout = facts/scores (no prose) → Scribe = prose for every card + the brief (LLM, can hallucinate) → Guard = re-asserts hard SEO facts over Scribe for the one card where hallucination is costly. Each stage is non-fatal: a failure logs a warning and downstream fills or skips. Scout failure → card skipped. Scribe failure → raw intake shown. Guard failure → falls back to Scribe's SEO card.
